# Recovery-first publication provenance and bounded LLM fallback

Status: design for user review; no runtime implementation or deployment.
Base: adf8fd677d0e0a122d7d09f2c9c622c63aa6a89b.

## Intent and approval boundary

Recover legitimate publication dates across publishers without a publisher-by-publisher patchwork or brittle formatting checks. The user approved moving beyond the isolated experiment and adding 120 seconds to the overall research budget. Preserve paper-only execution, risk controls, two distinct-publisher qualification, seven-calendar-day discovery event freshness, and the existing numerical source-age allowance (180 days). This document proposes the precise date-only semantics and integration for review before implementation planning. Deployment remains a separately verified rollout; no new market-data services, credentials, dependency installs, shared Hermes changes or cron-cadence changes are included.

## Evidence and alternatives

The isolated experiment is retained privately in test_artifacts/publication-hybrid-spike-20261021T064922Z. On ten real representations from seven URLs, nine had identifiable publication days: the full applicable current parser recovered five and hybrid parsing recovered nine. Twelve synthetic cases exercised four known publication dates and eight unknown/misleading cases. No wrong acceptances or validator-induced false rejections were observed; the sample is small, correlated, and not held out. A tool-free batch took 40.733 seconds. Unchanged production evidence filtering accepted only four real representations, exposing the date-only interface barrier.

Rejected alternatives: continue accumulating issuer-specific contracts (maintenance burden); let a model directly approve freshness (unsupported provenance risk); retain exact-instant-only acceptance (unnecessary rejection of legitimate day-only sources). Choose deterministic standard extraction plus bounded, content-grounded LLM interpretation and precision-aware freshness.

## Data and ownership

Add a project-owned publication observation: version, value, precision (day or instant), basis (structured metadata, visible publication context, or grounded model interpretation), source URL/returned-URL binding, content hash, parser version and supporting excerpt/location. Instant values require an explicit timezone. Day values remain YYYY-MM-DD, with no invented midnight or timezone. A visible clock without timezone does not become an exact instant; retain the supported day and optional unverified clock context. Do not overwrite existing trustworthy exact metadata with a model proposal.

Keep existing issuer-specific contracts working; adding the generic path does not retroactively invalidate their established outputs. Do not broaden low-trust provider claims into verified publication evidence. Public logs expose typed reasons only; private evidence retains bounded diagnostic details with 0700 directories and 0600 files. Carry observations through direct fetch, structured extraction, cache, evidence filtering and any source serialization consumed by qualification; review all readers before claiming integration complete.

## Interpretation and recovery flow

1. Reuse already-fetched article content. Prefer applicable publication metadata and existing accepted evidence; inspect/preserve machine-readable fields when available through existing project-owned transport. Do not claim the extraction provider supplies fields it actually drops, or patch shared Hermes to obtain them.
2. Use generic visible publication context without mandatory HTML classes, publisher allowlists or a literal 'Published' label. Preserve header/byline and date-adjacent context in bounded representations.
3. Collect unresolved source pages before synthesis; only pages that could improve a candidate's distinct-publisher bundle are eligible for model fallback. Existing admissible evidence proceeds without waiting for unnecessary interpretation.
4. One tool-free LLM batch per research run, maximum ten distinct pages. Allocate one useful unresolved page per shortlisted candidate first, then a second per candidate where it can add a distinct publisher; deterministic stable ordering avoids one candidate consuming all fallback slots. Limit each supplied page excerpt to 6,000 characters, prioritizing header/byline and date-adjacent context, at most 60,000 content characters plus fixed instructions/schema. If the existing transport's encoded-input admission is smaller, lower input before launch; never raise transport caps silently. The original retained content remains the citation witness.
5. The model returns an observation or unknown for each bound page, supporting excerpt/location, publication-vs-event/update interpretation and material conflicts. Do not supply evaluation labels or use model confidence as evidence. Page content is untrusted data, not instructions. The interpreter has no tools, browsing, broker access or execution capability.
6. Deterministic checks cover URL/content binding, real and supported date values, normalized citation presence, actual publication context, and material publication-date conflicts. Permit whitespace, entities and punctuation normalization; do not demand exact literal formatting or invented precision. An update date differing from an explicit original publication date is not itself a fatal conflict. Duplicate keys, malformed envelopes and instruction-based fabricated claims remain inadmissible.
7. Unknown/malformed/timeout results leave the affected source unverified; retain other valid batch members and existing evidence. Continue existing bounded alternative-source paths while time remains. One rejected page is not a whole-run infrastructure failure; insufficient final evidence still cannot qualify.
8. For cached undated pages, allow at most one project-owned fresh fetch per exact page when useful and within the shared recovery allowance; no global cache disable, forced provider, repeat model invocation or unbounded rescue. Deduplicate against already fetched pages. Persist only grounded successful interpretations by URL/content hash/parser version; unknown results must not pin an otherwise recoverable page for a day. Cache checked_at remains actual retrieval/check time, never publication time.

## Date-only freshness semantics: explicit policy decision

Keep exact timestamps on the existing instant-based freshness path, including current future tolerance and maximum age. For a validated day-only observation, compare calendar dates against the current UTC date: accept age from -1 through 180 calendar days inclusive. This keeps the existing numerical one-day future tolerance and 180-day age ceiling but explicitly uses day precision instead of pretending an instant is known. It is a precision-specific comparison, not proof of a UTC publication timezone, and may differ near an instant threshold by part of a day. Preserve the observation's precision in source output and audits. Dates older than 180 days are stale; dates more than one calendar day ahead remain unverified. Invalid/ambiguous role or material publication conflicts remain unknown and eligible for bounded recovery. The seven-day discovery event-date gate is separate and unchanged.

## Budget ownership and cron compatibility

Verified code today: alpha_radar.RESEARCH_ACTIVE_BUDGET_SECONDS=570; run_cycle research timeout=600 for both premarket and radar. Proposed values: active 690; research wrapper timeout 720. Autotrader timeout, protection jobs, and cadence unchanged.

Reserve at most 90 cumulative wall-clock seconds for publication recovery, shared across any scoped cache refresh, preparation, model startup/input/output, parsing and validation. At most one model invocation, advisory model effort <=45 seconds. Before every operation, recompute remaining time under both the recovery deadline and outer active deadline, preserving existing downstream evidence/synthesis/enrichment reservations. The other 30 newly authorized seconds provide bounded orchestration/cleanup headroom; unused time is not a mandatory delay. Do not enlarge discovery/focused/search URL/concurrency limits or unrelated per-stage caps. The new phase must not remain hidden inside the old evidence-stage cap; make its deadline/reservation ownership explicit in orchestration and diagnostics.

Existing scheduled-slot code pairs radar at :00/:20/:40 with autotrader at :15/:35/:55. A 720-second research wrapper nominally leaves 180 seconds before the paired execution slot; 690 seconds of active work nominally leaves 210 seconds. These are schedule arithmetic, not a dispatch-latency guarantee. Premarket's 09:00 producer/09:40 consumer has a larger gap. Actual cron dispatch, process startup and cleanup consume margin. Verify upstream scheduler/no-agent script timeouts admit the full wrapper envelope before rollout; if a shared timeout blocks it, stop and present the scoped remedy instead of changing global Hermes settings silently. Retain existing overlap/locking and fail-closed behavior; no forced submission when research is late.

## Tests and acceptance criteria

- Baseline full/raw tests in the isolated feature worktree using the existing no-install runtime and required pinned source fixtures. TDD: observe failures for new cases before implementation.
- Generic structured metadata and visible headers; model-grounded recovery; missing timezone/day-only fields; actual Tradeweb representation; legacy issuer contract compatibility; HTML/text metadata omission.
- Day-only ages -2/-1/0/179/180/181; exact-instant unchanged; UTC rollover; offset-bearing timestamps; update vs publication; invalid dates, unrelated events/copyright/related stories and material conflicts.
- Grounding normalization, duplicate/forged page IDs, wrong source/content hash, fabricated quotations/dates, prompt injection, duplicate JSON keys, mixed good/bad batch members and insufficient evidence. Include deliberately wrong model proposals, not just a correct model followed by a validator.
- Deadline advancement during preparation, input backpressure, shared scoped refetch/model timeout, downstream reservation, one invocation limit, fair page allocation, valid-source retention and child cleanup. Assert research-only timeout 720 and active budget 690, with autotrader and cadence unchanged.
- Prove all observed publication precision/basis survives extraction/cache/evidence/qualification serialization. Unknown dates do not become stale merely because missing; crawl/cache/event times never supply publication.
- Larger disjoint labeled real-page corpus before promotion; freeze labels before model calls, distinguish HTML/text pairs and fetch failures, score known-day recovery/false rejections/wrong acceptance/abstention/actual evidence acceptance separately. Measure end-to-end added latency and usage. No acceptance-rate quota or guarantee from a small sample.
- Independent review; green full/raw suites with zero operational-state mutations and zero process exits on both isolated and later production verification. No diagnostic orders.
